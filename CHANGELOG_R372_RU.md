# AirXonix Android r372: полностью новый ввод

- JNI принимает **отдельные нажатия и отпускания** семи виртуальных клавиш: стрелки, Enter, Escape, P. Старый атомарный флаг и `AndroidTouchMenu` из r369-r371 больше **не участвуют** в рабочем Android-вводе.
- Каждое касание, включая A/B длительностью менее одного игрового кадра, помещается в синхронизированную очередь C++. Игровой поток получает **один однокадровый импульс**, затем обязательный нейтральный кадр (повторное взведение исходного меню).
- Во время анимации/перехода нажатия остаются в очереди до готовности экрана. При смене экрана подтверждение со старого экрана блокируется до отпускания.
- Направления меняются без застревания. Удержание стика в меню повторяет движение через 350 мс, потом каждые 140 мс; в игре движение непрерывно.
- События Android-пульта имеют приоритет перед случайно оставшимися направлениями внешнего контроллера в меню. Bluetooth-контроллер по-прежнему работает, когда экранные кнопки не нажаты.
- Команда Android UI `nativeTouchReset()` очищает состояние при потере фокуса.
- Логи доступны через `adb logcat -s AirXonixTouch:D`, содержат реальные события UI и принятия их игрой.
- Рендер, игровая логика, исходный H700/PortMaster и текстовый ввод рекордов не изменены.
- Добавлен регрессионный тест `android_virtual_input_r372`: быстрые A/B, все направления, повтор, удержание в игре, fade-in, переключение экранов и реальная последовательность MainMenu -> ModeSelect -> B.

## Сборка
Android 8.0+, ARM64, SDL2, OpenGL ES2. GitHub Actions строит вариант с clean-room ресурсами; личная сборка включает оригинальные `AirXonix.wrp.exe` и `MUSIC`.

**Тесты не заменяют проверку на физическом Android-устройстве.**
