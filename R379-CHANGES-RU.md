# r379 — синхронизация совместной гибели и финала

Основа: полный исходный код r378. Обновлён сетевой протокол `AXMP` до **v5**.

## Изменения

- `src/game/coop_game.cpp`: устранён пропуск смерти красного Xonix при гибели обоих в одном кадре на последней жизни. Фатальные события одного кадра обрабатываются одним пакетом с маской игроков `deathMask=3`; lives_ уменьшается на число погибших с ограничением снизу нулём.
- `src/net/lan_protocol.hpp`: добавлены маска смертей, координаты второго столкновения и ключевые параметры финальной анимации. Добавлена валидация новых полей и отклонение NaN, неверных масок и завышенных значений.
- `src/game/coop_game.cpp`: клиент озвучивает оба столкновения по отдельности в нужных позициях и не дублирует их при повторной доставке снимка с тем же `deathSerial`.
- `src/render/legacy_hud.cpp`: добавлены `BOTH XONIX DOWN`, `CO-OP GAME OVER`, `CO-OP COMPLETE` и общий итоговый счёт. Работает только при включённом кооперативе; штатный HUD одиночной игры не изменён.
- Финальная сцена больше не застывает после последнего уровня: хост обновляет упрощённую восьмисекундную презентацию, передаёт высоту, координаты Xonix, фазу ротора и кинематографической пары; после этого обе консоли отображают Complete. Итоговые бонусы начисляются хостом один раз.
- `tests/test_lan_finish_r379.cpp`: тест сразу двух смертей при 3/2/1 жизни; тест логики через обычный игровой кадр; проверка клиентских звуков, финальной фазы, счёта и поддельных пакетов.

## Локальные проверки

- CMake Debug (`AIRXONIX_BUILD_RUNTIME=OFF`, `AIRXONIX_BUILD_TESTS=ON`) — сборка `airxonix_gamecore`, `airxonix_legacy_mesh` и сетевых тестов.
- `ctest -R '^lan_' --output-on-failure` — **6/6 PASS** (r374–r379).
- `test_lan_finish_r379` с `-fsanitize=address,undefined` — **PASS**.
- Наличие/сборка исполняемого ARM64 бинарника **не проверялись**, так как Linux SDL2/GLES2 runtime недоступен; тестирование на двух реальных RG40XX H также не проводилось.

## Оставшиеся ограничения

- Тесты подтверждают сетевую и игровую логику на host-сборке x86_64, не фактическую работу двух физических консолей.
- При Game Over совместная сессия остаётся на экране результата до системного выхода. Для повторной игры нужен будущий сетевой протокол перезапуска.
- Возможна потеря промежуточных последовательных событий гибели между редкими снимками мира (если несколько разных кадров гибели укладываются в один интервал передачи). Пакет r379 гарантирует два события *одного* кадра; очередь исторических событий остаётся отдельной задачей.
- Финальная сцена упрощена для кооперативного пути и не повторяет все single-player спецэффекты.
