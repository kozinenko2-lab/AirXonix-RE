# Графические режимы AirXonix r389 — H700 / OpenGL ES2

**Статус: реализовано в ветке PortMaster r389; аппаратная визуальная проверка ещё нужна.**
Выбираются в меню **Настройки → Графика** кнопками ←/→ или A.
Сохраняются в отдельный файл `gameinf.bin.graphics.ini`, без изменений
оригинального 36-байтного `gameinf.bin`.

| Режим | GLES2 | Дополнительные проходы | По умолчанию |
|---|---|---|---|
| ORIGINAL | Исходная формула `vLight` и GL_LINEAR | Нет | Да |
| SHARP | GL_NEAREST для 3D мира, UI остаётся GL_LINEAR | Нет | Нет |
| ENHANCED | Умеренная насыщенность и яркость 3D | Нет | Нет |
| TOON | Три ступени освещения в текущем GLSL fragment shader | Нет | Нет |

В меню и HUD принудительно возвращается режим ORIGINAL; графические эффекты
не передаются по сети и не влияют на RNG, столкновения или скорость симуляции.
В GL-шейдере у каждого кадра меняется только `uGraphicsMode`.
GLSL компилируется устройством при запуске; ARMHF-сборка доказывает корректность
C++-кода, но не фактическую компиляцию GLSL драйвером Mali в H700.
FXAA, тени SSAO, FBO и контурный Toon пока не реализованы.

## Главный логотип и вступление

Для главного титульного LOGO добавлен +90° поворот вокруг Y в native renderer.
Это экспериментальная поправка, не адресная реконструкция оригинального EXE.
В clean-room текстура `LOGO` — авторская схематичная замена, поэтому 90°
не может воспроизвести исходный зелёный логотип в точности.

Из восстановленных трасс 0x41D696→0x416110 и 0x41D071→0x416110 следует,
что летающие враги уже движутся и разрушают поле до приземления Xonix.
В r389 воздушные модели вынесены в отдельный draw-pass; в обеих вводных сценах
им даётся приоритет глубины, но Xonix рисуется после них с нормальным depth-test.
Бинарное сравнение с оригинальным EXE в этой итерации не проводилось;
визуальный результат следует проверить на консоли по фото или видео.
